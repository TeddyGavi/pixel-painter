# Bead palettes

One TSV per brand series is the source of truth. `gen_palettes.py` turns each into
`main/palette_<id>.c/.h`; the generated files are committed but never edited by hand.

```sh
python3 palettes/gen_palettes.py      # after editing any palettes/*.tsv
```

TSV columns: `code r g b name source note`.
- `code`: the manufacturer's colour code. It is what the order report lists.
- `source`: `label` (RGB printed by the manufacturer) or `photo` (sampled from a chart
  photo, approximate). The firmware's `bead_color_t.approx` is 1 for `photo`.
- `name`: descriptive and **unofficial** where the brand publishes no names
  (generated by `colorname.py`, then free to edit by hand).

Order in the TSV = order of chips on the device's palette strip.

## Artkal S (`artkal_s.tsv`): 225 colours, 5 mm midi, hard

- **Source:** Artkal's official S-series colour chart image ("S-5MM color chart, 225"),
  `https://cdn.shopify.com/s/files/1/1323/8195/files/artkal-beads-S-series-color-chart-_2.webp?v=1757662815`,
  linked from `https://www.artkalfusebeads.com/blogs/artkal-color-chart` (retrieved
  2026-11-10). Artkal publishes the chart only as an image: no text, CSV or PDF.
- **Codes and RGB (176 solid colours, S and SE):** the RGB printed on each swatch's label.
  Tiles were located on the chart grid, and each label was enlarged 4x and read by eye
  (Tesseract could not read the ~6 px digits reliably). Checks:
  - all 225 tiles found, matching Artkal's stated count;
  - all codes unique, all values 0-255;
  - every label was compared with the colour sampled from its own swatch photo. Hue
    disagreements were inspected individually. Only **S119** disagrees beyond photo
    lighting: its label says green (113,196,82) while the photo is pale mint. The
    printed label is kept, and this is noted in the TSV.
  - **SE06**'s label is identical to S24's (20,123,209); kept as printed.
- **Specialty beads (49, `source = photo`):** translucent ST1-8, glitter SL1-6,
  glow-in-the-dark SG1-7, neon SN1-4, pearl SP1-8, UV-changing SUV1-4 and two-colour
  striped SD1-12 carry no RGB on the chart. Their colour is the median of the swatch
  photo's bead pixels, so it is only an on-screen approximation. Names carry the type
  as a prefix (Clear, Glitter, Glow, Neon, Pearl, UV, Stripe).
- **Names:** the S chart prints no names (Artkal's slip has them; they are not on the
  web), so names are generated from the RGB: lightness plus hue family, with
  neutrals, browns, beiges and olives named separately. Several colours share a name;
  the code always disambiguates.
- `tools/extract_tiles.py` and `tools/sheets.py` are the scripts used to locate tiles and
  build the enlarged label sheets for reading.

Not included yet: Artkal's newer J midi range (S + J = 443 colours), and the other
series (R soft midi, C/A/M mini).

## Miyuki Delica (`miyuki_delica.tsv`): 254 of ~1,270 colours, 11/0 cylinder

- **Source:** Miyuki's Delica Beads colour chart, cards 1-7,
  `https://www.miyuki-beads.co.jp/common/data/pdf/N-2.pdf` (retrieved 2026-11-13). The
  PDF is seven 300 dpi photos of the printed cards: codes and bead strips only. It has
  no text layer, no RGB and no names.
- **Why 254:** the firmware stores a cell's colour as a `uint8_t` palette index, with
  `0xFF` meaning empty, so a palette holds at most 254 colours. The chart has about
  1,270 codes (DB, DBC cut, Duracoat, Picasso and so on).
- **Extraction:** a page-wide `tesseract --psm 11` pass found about 40-60% of the code
  labels. That was enough to fit each card's columns (with photo tilt) and its row
  pitch. Every cell was then cropped. Its label was binarised (gridlines removed) and
  read with `--psm 7`, and the bead strip beside it was sampled.
- **Colour (`source = photo`, all `approx = 1`):** the median of the strip's central
  bead band, white-balanced so the paper beside the strip reads 245. It is an on-screen
  approximation; the code is what matters for ordering.
- **Selection:** greedy farthest-point sampling in CIE Lab, seeded with DB-10 (black)
  and DB-200 (white). It is weighted toward uniform-looking beads (high
  `uniformity`, see below) over AB, metallic and mixed finishes. Every chart bead is
  within dE 16 of a shipped colour.
- **Codes are exact:** OCR confuses 5/6/7/8 on this font, so all 254 shipped codes were
  checked by eye against the label crop from the chart. All matched.
- **`sources/miyuki_delica_all.tsv`:** every cell found, with colour, `uniformity` (the
  share of bead pixels within dE 15 of the median) and card number. Only `verified=1`
  rows (the shipped set) have checked codes. The other codes are raw OCR, so check one
  on the chart before moving it into `miyuki_delica.tsv`. `gen_palettes.py` does not
  read `sources/`.
- **Names:** generated by `colorname.py`, as for Artkal. They are unofficial; Miyuki's
  names, such as "Opaque Luster Rose", are not in the PDF.

Perler (a 6-colour starter) was removed when Miyuki was added. Saved patterns store a
brand index, so `store.c` (pattern v4) remaps v2/v3 saves: Hama 1→0, Artkal 2→1. Old
Perler saves fall back to defaults.

Miyuki tools, in run order (scratch dir `S` holds `work/`): `tools/miyuki_cells.py`
(per page: grid, OCR, crops), `tools/miyuki_merge.py` (merge, flag bad OCR, duplicates
and out-of-sequence codes), `tools/miyuki_curate.py S 254` (colour, uniformity,
selection), `tools/miyuki_sheets.py` (verification contact sheets) and
`tools/miyuki_write_tsv.py S palettes`.
